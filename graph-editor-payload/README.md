# Graph Editor Payload

`:graph-editor-payload`: generates the catalog, the JSON description of a platform that the web editor draws its
nodes, ports and types from. It is the contract between the graph framework and the editor: the editor renders
palettes, ports, typed-in values and connection rules from the catalog without knowing any node itself.

## Overview

`CatalogGenerator.generate(platform)` turns a `GraphPlatform` from
[graph-compiler](../graph-compiler/README.md) into a `Catalog`:

- `format`: version of the catalog structure (`Catalog.FORMAT`, currently 1).
- `version`: the first 16 hex characters of a SHA-256 over the content, so user data can name the catalog it was
  made with.
- `nodes`: every node type, ordered by id. Besides the platform's nodes this includes the macro boundary nodes
  (flagged `macroOnly`, placeable only while editing a macro) and the routine boundary nodes.
- `types`: every concrete type used by a port, with its editor name, whether values can be typed in, the allowed
  values (such as enum constants) and the other types it is assignable to.
- `selectable`: the types users can pick themselves, for example for macro inputs.

A port's type is a `TypeRef` in exactly one of three forms: a concrete type id (described in `types`), a type
variable bound per node by what is connected, or a generic type whose arguments contain variables. An input is
marked `literal` when a value can be typed in instead of connecting a node, which is the case for types with a
literal codec and for inputs that accept a boolean, integer, number or text.

The output is deterministic: nodes and types are sorted and `write` emits indented JSON with sorted keys, so equal
platforms give equal JSON and equal versions.

`CatalogGenerator.withDescriptions(catalog, source)` fills empty node and port descriptions from another catalog of
the same platform, matched by node id and port id, and recomputes the version. Existing descriptions win. This lets
a catalog generated by a running server pick up the javadoc texts collected at build time.

## Layout

All classes live in `de.eldoria.graph.payload`:

- `CatalogGenerator`: `generate`, `read`, `write` and `withDescriptions`.
- `Catalog`: the top-level record.
- `NodeType`: one node the editor can place (kind, category, name, description, ports, executions, config).
- `PortInfo`: a data input or output, with the group a large node draws it under.
- `ExecutionInfo`: an execution output, with whether its chain may repeat.
- `ConfigInfo`: a config field with its default value, and the port it is drawn beside, if any.
- `TypeInfo`: a concrete type with its literal values, assignability and input format (e.g. `color`).
- `TypeRef`: the type of a port as the editor sees it.

## Using it

- `core` generates the catalog of its live platform, completes it with the bundled catalog's descriptions and sends
  it to the web backend when opening an editor session; it can also export it as `catalog.json`.
- `catalog` writes the bundled catalog with javadoc descriptions from the Paper API sources (task
  `generateCatalog`).
- `web-backend` reads catalogs with `CatalogGenerator.read` when a plugin uploads one, and stores them.

Changing a descriptor, a node set or a record in this module changes what the editor receives. The test
`CatalogGeneratorTest#matchesTheSnapshot` compares a catalog of the standard nodes plus two test nodes against
`src/test/resources/catalog-snapshot.json`. When a change is intended, regenerate the snapshot and review its diff:

```bash
./toolchain.sh be-snapshot   # ./gradlew :graph-editor-payload:test -Dsnapshot.update=true
```

## Dependencies

Depends on: [graph-compiler](../graph-compiler/README.md) (`api`); [graph-std](../graph-std/README.md) for tests
only.

Used by: `core` (`api`), `catalog` and `web-backend`.

```bash
./toolchain.sh be-test1 graph-editor-payload '*'

```
